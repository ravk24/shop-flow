# ShopFlow Phase 2 — Page Object Model: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Context

Phase 1 is merged to `main`: a Chromium-only Playwright project with one login test that uses raw `page.getByTestId` calls. Phase 2 (spec §8) introduces the Page Object Model: `BasePage`, `LoginPage`, `InventoryPage`, a shared `HeaderComponent`, the login test rewritten over page objects, the first inventory test (PROD-01), and a short README. Fixtures and storageState are Phase 4; data files are Phases 3 and 5. Execution method already chosen by the user: **Native** (superpowers:executing-plans) with explanations of the "Concepts to explain" at the end.

**Goal:** All specs import page objects instead of calling `page.getBy…`, PROD-01 passes, and a stranger can run the suite from the README.

**Architecture:** Page objects own locators (defined once in the constructor) and actions; tests own assertions. `HeaderComponent` is composed into `InventoryPage` as `this.header` (composition, not inheritance). Page objects are constructed directly in specs with `new LoginPage(page)` until Phase 4 adds fixtures.

**Tech Stack:** Node 24, `@playwright/test` 1.64, JavaScript (CommonJS).

**Spec:** `PROJECT_PLAN.md` — §5.1 (POM rules, `LoginPage` skeleton verbatim), §5.4 (locator priority), §8 Phase 2 (tasks, done-when, concepts), §9 (conventions).

**Verified SauceDemo markup (recon on 2026-10-31):**

| Element | Locator |
|---|---|
| Login fields / button / error | `getByTestId('username' \| 'password' \| 'login-button' \| 'error')` |
| Page heading "Products" | `getByTestId('title')` |
| Sort select | `getByTestId('product-sort-container')` |
| Product card (×6) | `getByTestId('inventory-item')` |
| Card name / desc / price | `getByTestId('inventory-item-name' \| 'inventory-item-desc' \| 'inventory-item-price')` |
| Card image | `img` inside the card (`data-test="inventory-item-<slug>-img"`, alt = product name) |
| Card button | `button` inside the card (`data-test="add-to-cart-<slug>"`, text "Add to cart") |
| Cart link / badge | `getByTestId('shopping-cart-link' \| 'shopping-cart-badge')` (badge absent when cart empty) |
| Burger open / close | `getByRole('button', { name: 'Open Menu' })` / `{ name: 'Close Menu' }` (the `data-test` sits on a decorative `img`, not the button) |
| Menu links | `getByTestId('logout-sidebar-link' \| 'inventory-sidebar-link' \| 'reset-sidebar-link' \| 'about-sidebar-link')` |

## Global Constraints

- JavaScript (CommonJS); classes exported as named exports: `module.exports = { LoginPage }`.
- Page object owns locators and actions; **never contains `expect`**. Tests own assertions.
- Locators defined once in the constructor as `this.x = page.getBy…`; no locator strings inside methods.
- Locator priority: `getByTestId` → `getByRole` → `getByText` → CSS last resort, never XPath.
- Web-first assertions only; no `page.waitForTimeout()`.
- Done-when for the phase: `grep -rn "page.getBy" tests/` returns nothing.
- Test titles: plain English, present tense, lowercase start, tags at the end.
- Branch `phase-2-pom`; imperative commit messages ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- No credentials or product strings hard-coded beyond the Phase 1 env-with-fallback pattern (data files arrive in Phases 3 and 5).

## Review Focus

1. **A page object that quietly asserts** — a `login()` that throws on the error banner would make Phase 3's negative tests impossible. Pinned by Task 1 Step 3: `login()` fills and clicks, returns nothing.
2. **Locator that matches more than the card** — `getByRole('img')` on the whole page would also catch the burger/close-menu icons (they are `img`s). Pinned by Task 2 Step 1: image and button locators are scoped inside `this.items`.
3. **Count assertion that passes on a half-rendered list** — `toHaveCount(6)` retries, but a name assertion on an empty locator passes vacuously. Pinned by Task 2 Step 1: `toHaveText` with a six-element array fails unless exactly six non-empty names render.
4. **Header locator duplicated per page** — `InventoryPage` must expose `this.header`, not re-declare badge/menu locators. Pinned by Task 3 Step 3 and the grep in Task 4 Step 3.
5. **README commands that don't exist yet** — only scripts present in `package.json` after Phase 1 may appear. Pinned by Task 4 Step 2.

### Task 2: PROD-01 — inventory lists six complete products

**Files:**
- Create: `tests/products/inventory.spec.js`
- Modify: `pages/InventoryPage.js`

**Interfaces:**
- Consumes: `LoginPage`, `InventoryPage` from Task 1.
- Produces on `InventoryPage`: `sortDropdown`, `items`, `itemNames`, `itemPrices`, `itemImages`, `itemButtons` locators (Phase 5 sorting/cart tests build on these names).

- [ ] **Step 1: Write the failing test**

```js
const { test, expect } = require('@playwright/test');
const { LoginPage } = require('../../pages/LoginPage');
const { InventoryPage } = require('../../pages/InventoryPage');

const username = process.env.STANDARD_USER || 'standard_user';
const password = process.env.PASSWORD || 'secret_sauce';
const PRODUCT_COUNT = 6; // Phase 5 replaces with data/products.js

test.describe('inventory', () => {
  let inventoryPage;

  test.beforeEach(async ({ page }) => {
    const loginPage = new LoginPage(page);
    await loginPage.goto();
    await loginPage.login(username, password);
    inventoryPage = new InventoryPage(page);
  });

  test('lists all six products with name, price, image and button @smoke', async () => {
    await expect(inventoryPage.items).toHaveCount(PRODUCT_COUNT);
    await expect(inventoryPage.itemNames).toHaveText(Array(PRODUCT_COUNT).fill(/\S/));
    await expect(inventoryPage.itemPrices).toHaveText(Array(PRODUCT_COUNT).fill(/^\$\d+\.\d{2}$/));
    await expect(inventoryPage.itemImages).toHaveCount(PRODUCT_COUNT);
    await expect(inventoryPage.itemButtons).toHaveText(Array(PRODUCT_COUNT).fill('Add to cart'));
  });
});
```

- [ ] **Step 2: Run it to verify it fails**

Run: `npx playwright test tests/products`
