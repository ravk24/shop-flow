## Global Constraints

- Language: JavaScript (CommonJS). No TypeScript.
- Test runner: `@playwright/test`. Browsers: Chromium only in this phase.
- `testIdAttribute: 'data-test'` — all element lookups via `getByTestId` where a `data-test` attribute exists.
- No `page.waitForTimeout()` anywhere.
- Web-first assertions only (`await expect(locator).toHaveText(...)`, never `expect(await locator.textContent())`).
- Credentials read from env (`STANDARD_USER`, `PASSWORD`) with the public defaults as fallback; `.env` git-ignored, `.env.example` committed.
- Test titles: plain English, present tense, lowercase start, tags at the end (e.g. `... @smoke`).
- Git: branch `phase-1-scaffold`, commit messages in imperative mood, end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Working directory is `C:\PrCa\shop-flow` (spec §12 says `~/shopflow`; ignore that path).
- Run shell steps in PowerShell 5.1: no `&&`; chain with `;`.

## Review Focus

1. **Missing `.env`** — a fresh clone without `.env` must still run the test; config falls back to the SauceDemo URL and the spec falls back to public credentials. Pinned in Task 4 Step 8.
2. **Local failures produce no trace** — `trace: 'on-first-retry'` with `retries: 0` locally means a broken test yields no trace.zip unless `--trace on` is passed. Pinned in Task 4 Step 5.
3. **Scaffold leftovers** — `create-playwright` writes `tests/example.spec.js` (and possibly `tests-examples/`) that hit playwright.dev; if left, `npm test` runs them. Pinned in Task 2 Step 3 and Task 4 Step 2 (`--list` shows exactly 1 test).
4. **Artifacts leaking into git** — `test-results/`, `playwright-report/`, `.auth/`, `.env` must be ignored before the first test run. Pinned in Task 1 Step 2 and Task 4 Step 9 (`git status` clean after a run).
5. **Blocking commands in an autonomous session** — `playwright show-report` and `show-trace` start servers / GUIs and never return; they are run in the background or handed to the user as commands, never awaited in the foreground. Pinned in Task 5.

- [ ] **Step 1: Write the test**

```js
// tests/auth/login.positive.spec.js
const { test, expect } = require('@playwright/test');

// Phase 1 only: raw locators and env reads live in the spec.
// Phase 2 moves locators to page objects; Phase 3 moves credentials to data/users.js.
const username = process.env.STANDARD_USER || 'standard_user';
const password = process.env.PASSWORD || 'secret_sauce';

test.describe('login', () => {
  test('logs in as standard_user and lands on inventory @smoke', async ({ page }) => {
    await page.goto('/');
    await page.getByTestId('username').fill(username);
    await page.getByTestId('password').fill(password);
    await page.getByTestId('login-button').click();

    await expect(page).toHaveURL(/\/inventory\.html$/);
    await expect(page.getByTestId('title')).toHaveText('Products');
  });
});
```

- [ ] **Step 3: Explain the four Phase 1 concepts in chat, in plain words, each tied to a line in the spec file**

- **Auto-waiting:** `getByTestId('login-button').click()` waits for the button to be attached, visible, stable and enabled before clicking. No `sleep`.
- **Web-first assertions:** `await expect(page.getByTestId('title')).toHaveText('Products')` keeps re-checking until it passes or the 5 s `expect.timeout` elapses. `expect(await locator.isVisible()).toBe(true)` checks once, instantly, and is why many frameworks are flaky.
- **Trace viewer:** the trace.zip from Step 5 contains every action, DOM snapshot, network call and console line; `on-first-retry` means CI gets it for flaky tests at no cost on green runs.
- **`baseURL`:** `page.goto('/')` resolves against `BASE_URL`, so pointing the whole suite at a staging host is a one-line `.env` change.
