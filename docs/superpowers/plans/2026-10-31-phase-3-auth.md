# ShopFlow Phase 3 — Authentication Suite: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Context

Phases 1–2 are merged to `main` and CI is green: page objects exist for login and inventory, a `HeaderComponent` is composed into `InventoryPage`, and three tests pass. Phase 3 (spec §8) completes the authentication suite AUTH-01 to AUTH-09, introduces `data/users.js`, adds the `@negative` and `@regression` tags with matching npm scripts. Fixtures and storageState remain Phase 4, so every test in this phase still starts from a fresh browser context and logs in through the UI. Execution method already chosen: **Native** (superpowers:executing-plans), with concept explanations at the end.

**Goal:** AUTH-01 to AUTH-09 pass on Chromium, `npm run test:negative` runs exactly the six negative tests, and no spec reads credentials from `process.env` directly.

**Architecture:** `data/users.js` is the single source of credentials (env with public defaults). Negative login cases are a data-driven `for…of` loop in one spec. `LoginPage` gains the error-dismiss button and `dismissError()`; `HeaderComponent` gains `logout()`. Tests keep owning every assertion.

**Spec:** `PROJECT_PLAN.md` §5.5 (test data), §5.6 (tagging), §6.1 (AUTH scenarios), §8 Phase 3, §9 (conventions).

**Verified SauceDemo behaviour (recon on 2026-10-31):**

| Scenario | Observed |
|---|---|
| locked_out_user | error text `Epic sadface: Sorry, this user has been locked out.` |
| valid user, wrong password | `Epic sadface: Username and password do not match any user in this service` |
| both fields empty | `Epic sadface: Username is required` |
| username only | `Epic sadface: Password is required` |
| error dismiss | `<button data-test="error-button" aria-label="Dismiss error">` inside the `data-test="error"` `<h3 role="alert">`; after click the error element is removed |
| direct `/inventory.html` logged out | redirected to `/`, error `Epic sadface: You can only access '/inventory.html' when you are logged in.` |
| performance_glitch_user | stalls the page for about 5 s after login (the original recon missed this). `page.evaluate` stalls the same way, which points to a blocked main thread. `toHaveURL` passed 24/24 at limits of 100 ms, 1 s and 4 s, so no raised timeout is needed |
| logout | burger → `logout-sidebar-link` → lands on `/`; login button renders a moment later (web-first assertion handles it) |

The spec's §6.1 expected texts are substrings of the above; tests assert the **full** text so a copy change is caught.

## Global Constraints

- JavaScript (CommonJS); page objects never contain `expect`; locators only in constructors.
- Credentials only via `data/users.js`; `grep -rn "process.env" tests/` must return nothing after Task 1.
- Tags in titles: `@smoke` (AUTH-01, PROD-01 unchanged), `@regression` on every other test, and additionally `@negative` on the six negative tests. `test:regression` therefore runs everything except smoke; `test:negative` runs only the six.
- Data-driven titles must be unique: include the case name.
- Web-first assertions; no `waitForTimeout`; no `page.getBy…` in specs.
- Branch `phase-3-auth`; imperative commits ending `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Shell chains must check the test run's exit code, never a `grep`'s.

## Review Focus

1. **Negative tests must start logged out.** Today every test gets a fresh context, so this holds implicitly; Phase 4's storageState would silently log them in. Pinned now by a comment block at the top of `login.negative.spec.js` naming the Phase 4 `test.use({ storageState: { cookies: [], origins: [] } })` requirement, and re-pinned by the Phase 4 plan.
2. **An assertion that can't fail.** Each negative case asserts the full error string; Task 2 Step 3 mutates one expected string and watches the run fail.
3. **Glitch-user flakiness.** If AUTH-09 ever exceeds the 5 s expect timeout, raise only that assertion's timeout with a comment, never the global one. Pinned by Task 4 Step 5.
4. **Logout that only changes the URL.** AUTH-02 asserts both the `/` URL and the visible login button, so a logout that navigates without rendering the form fails. Pinned by Task 4 Step 1.
5. **Data file that ignores `.env`.** Task 1 Step 1 runs the module with an env override and expects the override to win.

### Task 2: Negative login suite — AUTH-03, AUTH-04..06 data-driven, AUTH-08

**Files:**
- Create: `tests/auth/login.negative.spec.js`

**Interfaces:**
- Consumes: `LoginPage` (`goto`, `login`, `errorMessage`), `InventoryPage.goto()`, `users`.

- [ ] **Step 1: Write the spec**

Header comment (Review Focus 1):
```js
// These tests must start logged out. Phase 4 adds storageState for all other
// specs; when it does, this file needs test.use({ storageState: { cookies: [], origins: [] } }).
```

Tests, all inside `test.describe('login - negative', …)`, each title ending `@regression @negative`:

```js
test('shows locked out error for locked_out_user @regression @negative', …)
  // login(users.lockedOut) → expect(loginPage.errorMessage).toHaveText('Epic sadface: Sorry, this user has been locked out.')
  // and expect(page).toHaveURL(/saucedemo\.com\/$/)

const invalidLogins = [
  { name: 'wrong password',      username: users.standard.username, password: 'wrong_password', error: 'Epic sadface: Username and password do not match any user in this service' },
  { name: 'empty username and password', username: '', password: '', error: 'Epic sadface: Username is required' },
  { name: 'empty password',      username: users.standard.username, password: '', error: 'Epic sadface: Password is required' },
];
for (const c of invalidLogins) {
  test(`shows "${c.error}" for ${c.name} @regression @negative`, …)
    // login(c.username, c.password) → toHaveText(c.error); URL stays /
}

test('redirects direct navigation to inventory back to login with an error @regression @negative', …)
  // inventoryPage.goto() → expect(page).toHaveURL(/saucedemo\.com\/$/)
  // → expect(loginPage.errorMessage).toHaveText("Epic sadface: You can only access '/inventory.html' when you are logged in.")
```

Use a `test.beforeEach` that constructs `loginPage`/`inventoryPage` and calls `loginPage.goto()` (the AUTH-08 test then navigates away from it, which is fine).

- [ ] **Step 2: Run — expected GREEN against the live app**

Run: `npx playwright test tests/auth/login.negative.spec.js; echo exit=$?`
Expected: `5 passed`, `exit=0`. (The app already behaves this way; the RED proof is the next step.)
